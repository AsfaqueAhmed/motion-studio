# Contributing

This is currently a solo/small-team project in the planning-to-implementation
transition. Until an external contribution process is needed, the working
rules are simply:

1. Read `ARCHITECTURE.md`, `DECISIONS.md`, and `GLOSSARY.md` before writing
   code or docs in any subsystem folder.
2. If you find a new instance of a subsystem being redefined in two
   places, or a term being used ambiguously, add an ADR to `DECISIONS.md`
   or an entry to `GLOSSARY.md` rather than silently picking one and
   moving on — keep the resolution visible for whoever reads this next.
3. Follow `STYLE_GUIDE.md` for naming and structural conventions.
4. Prefer expanding a stub file with what you actually learn while
   implementing over pre-writing exhaustive speculative detail — see the
   note in `README.md` about why most subsystem docs are intentionally
   left as stubs for now.
